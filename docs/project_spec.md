# 서울시 출퇴근 교통혼잡 완화를 위한 데이터 분석 및 AI 기반 교통정책 시뮬레이션

> 사용자가 제공한 기획서 원문(2026-10-19). 작업 요구사항의 기준 문서.

## 1. 프로젝트 목적

2026년 교통문제 해결 데이터 분석 공모전 제출을 목표로 한다.

**연구 주제:** 서울시 출퇴근 교통혼잡 완화를 위한 AI 기반 혼잡구간 분석 및 맞춤형 교통수요 관리 정책

서울 전역을 분석 대상으로 하며, 기존 정책 아이디어인 차량 홀짝제와 버스 증편을 검토한다.

단, 차량 홀짝제의 효과를 미리 전제하지 않고 실제 데이터 분석 결과를 통해 정책의 타당성을 판단한다. 필요하면 혼잡구간·시간대별 선택적 차량 수요 관리 정책 등 대안을 제안한다.

**핵심 연구 질문**

1. 서울에서 출퇴근 교통혼잡이 가장 심각한 지역과 시간대는 어디인가?
2. 교통혼잡은 차량 통행량, 요일, 날씨, 대중교통 수요와 어떠한 관계가 있는가?
3. 차량 홀짝제 또는 선택적 운행 수요 관리가 혼잡을 줄일 가능성이 있는가?
4. 차량 이용 감소로 발생하는 대중교통 추가 수요를 수용할 수 있는가?
5. 시민 이동 편의성, 형평성, 환경 영향을 함께 고려했을 때 어떤 정책이 가장 적절한가?

## 2. 데이터 확보

다음 공공데이터 플랫폼을 활용한다.

- 서울 교통빅데이터플랫폼: https://t-data.seoul.go.kr/
- 서울 열린데이터광장: https://data.seoul.go.kr/
- 공공데이터포털: https://www.data.go.kr/

우선 사용할 데이터는 다음과 같다.

### 필수 데이터
- 1시간 소통정보(구간별)
- 스마트교차로 1시간 교통량
- 서울시 교통량 이력 정보
- 서울시 지하철 역별 시간대별 승하차 인원 정보
- 서울시 버스노선별 정류장별 시간대별 승하차 인원 정보

### 추가 데이터
- 교통카드 대중교통 이용정보
- 버스 노선 및 통행속도 통계
- 서울시 교통량 지점 정보
- 기상청 시간대별 기상관측 자료
- 공휴일 및 행정구역·도로 공간정보
- 차량 유형별 교통량 및 배출계수 관련 공공자료

원시데이터의 접근 가능 여부, 이용 기간, API 명세, 호출 제한과 파일 형식을 확인한다.

가능하면 2024~2025년 데이터를 우선 확보하고, 2026년 데이터를 사용할 수 있다면 최신 기간까지 확장한다. 기간이 다른 데이터는 함부로 합치지 않는다.

API 키가 필요한 경우 임의의 키를 사용하거나 하드코딩하지 말고 사용자에게 발급받을 API 키 이름과 정확한 발급 URL을 알려준다. 환경변수(.env)를 사용하고 .gitignore에 추가한다.

CSV만 제공되는 데이터는 공식 다운로드 링크와 파일명을 알려준다.

## 3. 데이터 전처리 및 통합

Python을 사용한다.

사용 라이브러리:
pandas, numpy, geopandas, matplotlib, seaborn, plotly, folium, scikit-learn, xgboost, lightgbm, shap 등.

필요한 라이브러리는 requirements.txt에 명시한다.

전처리 요구사항:

1. 데이터 구조 및 컬럼 자동 점검
2. 한글 인코딩 처리
3. 결측값 및 중복값 확인
4. 비정상 속도와 교통량 이상치 분석
5. 날짜 및 시간 형식 표준화
6. 출근(08~10시) 및 퇴근(17~19시) 구분
7. 평일·주말·공휴일 구분
8. 지역 및 도로 구간 매핑
9. 행정동·자치구별 집계
10. 공간 및 시간 단위가 서로 다른 데이터의 통합 가능성 검증

결측값을 무조건 평균으로 대체하지 않는다. 원인과 비율을 확인하고 처리 방식을 기록한다.

## 4. 탐색적 데이터 분석(EDA)

최소 12개 이상의 의미 있는 시각화를 제작한다.

### A. 서울시 교통혼잡 현황
- 시간대별 교통량 및 평균속도 변화
- 평일과 주말 비교
- 월별·계절별 혼잡도 비교
- 출근과 퇴근 시간대 혼잡 집중 구간 비교

### B. 공간적 혼잡 분석
- 서울 자치구별 평균속도 지도
- 도로 구간별 혼잡도 지도
- 혼잡 상위 20개 도로 구간
- 시간대별 혼잡 핫스팟 변화

### C. 대중교통 수요
- 지하철 시간대별 승하차 패턴
- 버스 정류장 및 노선별 이용량
- 도로 혼잡과 주변 대중교통 이용 패턴 비교
- 추가 대중교통 수요 발생 가능 지역 파악

### D. 외부 요인 분석
- 강수 여부와 교통속도 비교
- 요일 및 공휴일 효과
- 차량 통행량과 속도 간 관계

그래프는 한국어로 작성하며, 보고서에 사용할 수 있도록 300DPI 이상의 PNG 및 가능한 경우 SVG로 저장한다.

Plotly를 활용한 인터랙티브 HTML 시각화도 제작한다.

시각화는 보기 좋게 구성하되 3D 그래프 등 시각적 효과가 데이터 해석을 방해하지 않도록 한다.

## 5. AI 기반 교통혼잡 예측

EDA를 통해 데이터 규모와 품질을 먼저 확인하고 예측 문제를 정의한다.

가능하면 다음 모델을 비교한다.

- 과거 동일 시간대 평균 등 단순 베이스라인
- Random Forest
- XGBoost
- LightGBM

예측 대상:
- 도로별 다음 시간대 평균 통행속도 또는
- 혼잡 여부 / 혼잡도

평가:
- 회귀: MAE, RMSE
- 분류: F1-score, Precision, Recall
- 시계열 순서에 따른 Train/Validation/Test 분할
- 데이터 누수 여부 점검
- SHAP을 이용한 예측 영향 요인 분석

복잡한 모델이 베이스라인보다 개선되지 않으면 그 결과를 그대로 보고한다.

## 6. 정책 시뮬레이션

반드시 아래 정책을 비교한다.

**시나리오 A: 현행 상태 유지**
- 관측 자료를 기준으로 정책 미적용 상태 정의

**시나리오 B: 서울 전역 출퇴근 차량 홀짝제**
- 출근 08:00~10:00, 퇴근 17:00~19:00
- 날짜와 차량 번호 끝자리의 홀짝 일치 방식
- 차량 통행량 감소율은 임의로 50%로 단정하지 않는다.
- 예외 차량, 순응률, 운행 일정 변경, 차량 대체 이용 등을 고려한다.

**시나리오 C: 혼잡지역 선택적 차량 수요 관리**
- 혼잡이 심한 지역과 시간대에 한정
- 대중교통 접근성과 우회 통행 영향을 고려

**시나리오 D: 버스 증편 및 대중교통 수요 분산**
- 혼잡 구간의 추가 대중교통 공급
- 수단 전환에 따른 수요 변화 추정

**시나리오 E: 선택적 수요 관리 + 대중교통 개선**
- 차량 수요 관리와 버스 증편의 결합

### 시뮬레이션 방법

가능하다면 교통량-속도 관계에 기초한 모형을 구축한다.

단, 단순 상관관계를 인과효과로 해석하지 않는다.

차로 수, 도로 용량, 차량 유형별 정보가 부족하다면 실제 정책 시행 효과를 확정적으로 예측하지 말고 가정 기반 민감도 분석으로 구분한다.

차량 통행량 감소율, 정책 준수율, 대중교통 전환율을 여러 구간으로 나누어 시뮬레이션한다.

성과지표:
- 평균 통행속도 변화
- 추정 통행시간 변화
- 혼잡 도로 비율 변화
- 대중교통 추가 수요
- 잠재적 초과수요
- 추정 CO2 배출량 변화
- 교통약자 및 대중교통 취약지역 영향

데이터만으로 산출할 수 없는 지표는 필요한 추가 가정과 불확실성을 명시한다.

## 9. 작업 원칙

- 실제 존재하는 데이터만 사용한다.
- 데이터를 확보하지 못하면 임의의 분석 결과를 만들지 않는다.
- 모의데이터는 코드 동작 검증 목적으로만 별도 폴더에서 사용한다.
- 실제 분석 결과와 가정 기반 시뮬레이션을 엄격히 구분한다.
- 모든 핵심 수치의 산출 근거와 출처를 기록한다.
- 주요 그림에는 데이터 기준 기간, 단위, 분석대상을 표기한다.
- 재현 가능한 Python 코드를 작성한다.
- 필요한 API 키나 파일은 구체적으로 요청한다.
- 결과물은 공모전에서 사용할 수 있는 수준의 분석보고서를 목표로 한다.

**우선 실행할 작업**

1. 공공데이터의 실제 접근 가능 여부 확인
2. 필요한 API 키 및 CSV 목록 작성
3. 데이터 수집 코드와 프로젝트 구조 생성
4. 확보 가능한 데이터를 기준으로 전처리 및 EDA 수행
5. AI 모델과 정책 시뮬레이션 구축
6. 분석보고서 작성

가능한 작업은 직접 실행하고, 인증키나 접근 권한 때문에 진행할 수 없는 부분만 나에게 요청해줘.
